# 基于反事实 Reference 与置信度的 In-Context Localization 强化学习方案

## 1. 核心动机

模型在 Query 中预测出正确目标，并不充分说明它使用了 Reference。例如，Reference 指向目标 A，模型也正确定位了 A，但可能主要依靠 Query 中的视觉显著性、类别先验或语言先验；替换 Reference 后，它仍可能输出原来的框。

因此，本方案希望同时考察两件事：模型能否正确定位，以及模型的目标选择与置信度能否随 Reference 的有效变化而变化。单独提升 mIoU 不足以回答第二个问题。

## 2. 多候选框与置信度

建议模型输出：

\[
(Q,R)\longrightarrow\{(B_i,C_i)\}_{i=1}^{K},\qquad C_i\in[0,1].
\]

其中，\(B_i\) 为 Query 中的候选框；\(C_i\) 的拟议语义为“该候选框正确定位了 Reference 指定目标的概率”，正确性由预先固定的匹配规则与 IoU 阈值 \(\tau\) 定义。它不是框的物体显著性，也不直接等同于生成文本的 token 概率。模型报出的数值是否具有概率意义，需要校准评估。

最终预测取 \(i^*=\arg\max_i C_i\)，并预先约定并列时的选择规则。若任务包含目标不存在的情形，可在 \(\max_i C_i<t\) 时拒答；阈值 \(t\) 只在独立验证集上确定。各候选置信度不必相加为 1，以允许所有候选均不可靠。

初始比较建议固定每个实验组的候选数 K、框格式、排序协议及输出长度上限；把改变 K 作为独立变量，避免把输出更多候选本身当作收益。

## 3. 反事实 Reference 的构造

固定 Query，改变 Reference，构造具有明确期望行为的配对条件：

| 条件 | 数据前提 | 期望行为 |
| --- | --- | --- |
| Reference 指向 A | Query 中存在 A | 正确选择 A，且对其置信度较高 |
| Reference 改为 B | 同一 Query 中存在可区分的 B | 选择转向 B；对原目标 A 的匹配置信度下降 |
| Reference 指向不存在的目标 | 标注能确认目标不存在 | 低置信度或拒答，避免自信误检 |
| Reference 改为同一目标的另一视角 | 目标身份保持不变且仍可识别 | 保持目标选择，检验对无关外观变化的稳定性 |

“换 Reference”不自动意味着“负样本”。A→B 条件要求定位转移，不应压低所有候选的置信度；目标缺失条件才要求整体降低置信度。随机抽取的 Reference 也不能未经核验便认定为负样本。

A、B 的身份或类别语义、同类多实例的匹配规则以及遮挡/歧义排除规则均须在数据构建前确定。优先使用自然存在多个可区分目标的 Query；如使用合成编辑，应单列报告，避免编辑痕迹成为捷径。

## 4. 拟议奖励设计

建议将奖励分为定位、置信度校准与 Reference 配对一致性三部分：

\[
r=\lambda_{\rm loc}r_{\rm loc}
 +\lambda_{\rm cal}r_{\rm cal}
 +\lambda_{\rm cf}r_{\rm cf}.
\]

各权重及阈值均待确定。以下仅定义可讨论的奖励含义，不是已批准的训练配置。

**定位项。** 对目标存在的样本，使用最终选中框与对应真值的 IoU，而不只奖励候选集合中的最佳 IoU。目标缺失样本单独定义拒答/误检得分。候选集合的 oracle IoU 留作诊断，以区分“找到好框”和“选中好框”。

**校准项。** 令 \(y_i=1\) 表示框 \(B_i\) 符合 Reference 匹配规则且达到 IoU 阈值，否则为 0，可采用：

\[
r_{\rm cal}=-\frac1K\sum_{i=1}^{K}(C_i-y_i)^2.
\]

不能直接奖励置信度数值大，否则模型可能通过统一输出高分获利。此项也不能单独使用：候选框由模型选择时，全部输出错误框并给低分仍可能获得良好校准得分，必须结合定位项及有效框检查。

**反事实项。** 对 A/B 切换，鼓励最终预测在两个方向上都正确：\((Q,R_A)\) 选择 A，\((Q,R_B)\) 选择 B。若还要比较“同一个框”的置信度差，应增加固定候选框评分的诊断协议，定义 \(s(B\mid Q,R)\)，再检查：

\[
s(B_A\mid Q,R_A)>s(B_A\mid Q,R_B),\qquad
s(B_B\mid Q,R_B)>s(B_B\mid Q,R_A).
\]

自由生成的第 i 个框可能在两次输出中指向不同对象，不能直接相减其置信度。固定框评分属于额外协议，不能与自由生成置信度混为一谈；是否纳入训练奖励须另行确定。目标缺失条件和同目标视角变化也应分别计分，避免奖励模型对任意输入变化都作出响应。

## 5. 与 GRPO 训练的衔接

拟议训练单元为一条完整的“候选框与置信度列表”，而不是把列表内的 K 个框当作 K 次独立 rollout。对同一输入采样 G 条完整输出，逐条计算奖励；K 控制候选数，G 控制训练采样数，两者应分别记录。

如果反事实奖励依赖两个 Reference 条件的联合行为，需要预先明确成对采样、配对方式及奖励归属，防止奖励差异仅来自随机配对。具体 GRPO 实现、组内奖励无方差时的处理、策略约束、无效输出处理及训练预算均待选型，本笔记不提供已验证的优化器配方。

## 6. 建议对照与评价

建议先讨论以下逐级比较，正式组别尚未登记：

| 建议组别 | 主要回答的问题 |
| --- | --- |
| 单框定位基线 | 原有定位能力如何 |
| K 框及置信度，定位奖励 | 多候选与选框协议的联合影响如何 |
| 上一组加校准奖励 | 显式校准是否改善置信度与选择 |
| 上一组加反事实奖励 | Reference 配对约束是否带来额外收益 |

固定模型初始化、数据划分、训练预算口径和解码配置，报告实际生成 token 数与推理成本；多个 K 的比较需明确是否匹配总计算预算。上述递进对照仍不能完全分离输出协议变化与训练变化，必要时增加相同输出协议的无强化学习对照。

建议同时报告：最终选框 mIoU、oracle@K IoU、两者差距、双向 Reference 切换均成功的配对比例、置信度 Brier 分数和可靠性图。若任务包含目标缺失，再报告误检率及拒答后的覆盖率—定位质量关系。固定框评分的置信度差单列为诊断。

所有错误格式、无有效框和拒答样本都应记录并纳入预先定义的计分规则，不能直接丢弃。置信度校准同时检查全部候选与最终选中候选。数据划分应避免相同 Query、目标身份或序列跨训练/评估泄漏；统计区间按相应独立单位计算，而非把配对条件当作独立样本。

## 7. 预期判读与待定事项

若 oracle@K 提高而最终选框指标没有提高，只能说明候选覆盖改善；若置信度差扩大但目标切换失败，只能说明输出分数发生变化。更有说服力的证据需要同时体现正确的目标切换、可靠的置信度，以及同目标 Reference 变化下的稳定性。

即使上述指标改善，也仅支持测试分布内的 Reference 条件化行为改善，不能单凭这些行为证明内部因果机制，更不能预先宣称方法有效或具有新颖性。

执行前仍需确定：模型与数据、目标匹配语义、K/G、IoU 和拒答阈值、奖励权重、训练与推理预算、随机种子、主指标、成功/失败标准，以及截断原文中是否还有必须保留的设计。当前没有实验结果，本草案不构成运行授权。
