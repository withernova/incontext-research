## 方向 3：Reference 成对监督

现有 `tools/prepare_candidate_selection.py` 的 `manifest` 只处理 GOT10k / LaSOT 的单目标同实例对，不能用该入口现有的 `verified` 字段证明多实例换 Reference 后的答案。

实现位置拟为现有准备 CLI 的新子命令，加一个按职责命名的身份核验模块。首版应支持一种明确的标注契约，拒绝未知格式；不声称自动兼容所有数据集。若采用 TAO 原生标注，需要实际核对其文件 schema 后才能宣称已适配。

输入至少包括：

- 绑定 SHA 的身份标注、冻结候选和排除组清单；
- Query 图像身份及两个不同实例的标注引用；
- 两个 Reference 的图像及实例标注引用；
- 图像 SHA、视频组、split 和原始来源；
- 同一份候选框及相同顺序。

核验必须从标注重建实例对应关系、框和答案，不能相信调用方填写的正确编号或 `verified=True`。两个目标均需有唯一且足够好的候选，且正确编号不同。记录接受与拒绝原因，按视频组隔离；验证集不能包含当前模型已训练过的组。

输出复用现有编号＋EOS SFT 行，保留 pair ID、实例 ID、标注来源和两行的共享候选证据。首版不改变 batch 访问方式、不增加成对 loss，也不承诺未核实的数据规模。

## 方向 6：续训学习率衰减

现有 SFT runner 在 `optimizer.step()` 后调用 `scheduler.step()`。checkpoint 会恢复 optimizer 和 scheduler，单独覆盖 `optimizer.lr` 会被恢复状态覆盖。

拟增加默认关闭的显式调度配置，支持线性和 cosine。参数包括开始更新编号、结束更新编号、结束倍率，以及恢复时允许迁移策略的开关。保持原 warmup、AdamW 状态、历史、样本进度和总更新预算。

约定学习率以实际更新编号 u 定义。以 step4041 恢复为例，第一步为 u=4042，最后一步为 u=5388。衰减区间 `[s,e]` 的进度为 `t=(u-s)/(e-s)`；线性倍率为 `1-(1-f)t`，cosine 倍率为 `f+(1-f)(1+cos(πt))/2`，其中 f 为显式结束倍率。端点包含在实际更新中，不能只在最后一步之后才达到目标 LR。

checkpoint 保存调度策略及迁移记录；恢复时核对策略、端点、总预算和 scheduler 进度。省略新策略不得使已有衰减 checkpoint 静默退回常数策略。调度元信息须在 `after_run` 写指标之前准备好。

原完成门禁保持：同固定 batch loss 下降、adapter delta 大于 0、有限梯度比例为 1。
