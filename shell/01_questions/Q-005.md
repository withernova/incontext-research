 二、GPT 这版真正成立的贡献

 修复版把“不要再往 query 里塞 reference 的 attention/residual”讲清楚了，并且与仓库事实对齐：

 - 已死路线：Q→R shape rewrite（R-003b/c 近零）、whole-residual 注入（R-006c 负、已停 family）。
 - 半成品：R-007 证明 reference↔query 在 pre-RoPE K 空间存在可读出的 correspondence，但自然 forward 没有把它转化成 query-side Q→Q/IoU——这正是“correspondence
   有用但模型没用上”的最强提示。
 - 真缺口：把 R-007 已验证的 correspondence map 用作显式 bias，去 steer query head 的 Q→query-image（pre-softmax），做成一个 oracle/causal gate。

 这条链与所有已跑 run 都有实质区别（不是 post-softmax A、不是 residual、不是观察、不是输入像素），且正面回答 Q-004 的核心：“必须最终改变 query head 对 query
 image 的 attention”。我认同这是当前最干净的下一步。

 三、采纳前必须补上的三个边界（GPT 没提，但项目规范要求）

 1. 这是 oracle/GT-conditioned gate，不是可用方法。 C_{R→Q} 的构造用了 reference GT object tokens 定义 (B_R)（R-007 也是这么定义的）。所以它只能回答“模型能不
    能用上 reference 信息”，不能宣称是无标注的 steering 方法。与 Q-004 对 GT-conditioned probe 的严格区分保持一致。
 2. 量纲/空间不匹配。 C 是 pre-RoPE K 空间的 cosine，S_{Q→Q} 是该 head 自身 QK 的 attention score；把 cosine 直接加到 QK score 上是两个空间/尺度的混合。必须先
    预注册归一化/缩放方案（例如把 C 转成同尺度的 mask 或乘性 gate），并配 identity/scale-only 对照，否则正负结果都无法归因。
 3. n20 只做 gate，不做确认。 若 oracle bias 都不能 rescue，则“correspondence 有用但未利用”的假设被明显削弱；若能 rescue，才值得进一步研究“不显式改 score、用
    ΔQ 让模型自然产生近似 attention”。任何结论不得在小样本上升级为 Finding/Claim。
