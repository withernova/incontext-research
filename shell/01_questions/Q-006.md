# Q-006 · 已有 Reference bbox 先验时，为何自然 Query-bbox 生成仍难由固定 heads 定位 Reference；GT 辅助的 head 发现能揭示什么？

## 原始疑问

IPLoc-ID prompt 已向模型提供 Reference image 及其 bbox 坐标先验，因此 Reference 目标区域不是完全未知的。可是，在模型自然生成 Query bbox 时，以自然 Query bbox token 的 `p−1` rows 读取到 Reference image tokens 的逐头注意力，并沿用 LocalizationHeads 式无 GT 选择后，很难得到一批同时满足以下条件的固定 heads：

1. 跨图片反复出现；
2. 在 selection-held-out Reference 图像上指向 Reference GT；
3. 明显优于同层随机或一般图像预算对照。

因此核心问题是：

> Reference bbox 已在 prompt 中给定时，模型为什么没有在自然 Query-bbox 生成阶段通过一批固定、可复用的 heads 回看 Reference 目标？这是 Reference 信息已被早期编码后无需持续空间回看、跨样本由不同 heads 动态承担、当前无 GT 排序准则选错了 heads，还是自然 bbox rows 对 Reference 的空间信号本来就弱？

第二个问题是：

> 由于每张 Reference image 都有对应 GT bbox，若将 GT 仅用于诊断或监督式 head 发现，能否找到无 GT LocalizationHeads 排名遗漏的 Reference-responsive heads，并进一步区分“信号不存在”与“算法找不到信号”？

## 已有证据与边界

### 1. R-003 的固定-head负面现象

E010-R-003 使用相同的自然 Query bbox `p−1` rows，分别在 Query 和 Reference image spans 上独立运行严格二值连通域 token-count entropy 与跨样本 frequency 选择。其已生成 artifact summary 显示：

```text
selection-held-out n=70
Qbbox→Query 固定 query heads：
  Top3 pointing rate = 68.57%
  Top5 pointing rate = 68.57%

Qbbox→Reference 独立发现的固定 reference heads：
  Top3 pointing rate = 2.86%
  Top5 pointing rate = 0%
```

该结果支持“当前固定无 GT Reference-head名单缺乏 Reference GT 空间有效性”，但不等价于“模型完全不使用 Reference”。R-003 的治理 completion 曾受 metrics declaration contract 阻塞；因此这里将数值视为已生成 artifact 的实验观察，正式综合仍应以 canonical analysis/归档核验为准。

### 2. Per-image GT oracle 表明部分图像中存在可读出的 Reference head

旧 E010-R-001 在同一批 held-out Qbbox→Reference 全头 maps 上做过 per-image GT oracle：每张图从全部 1152 heads 中事后选择空间指标最佳者。结果为：

```text
n = 70
pointing rate = 61.43%（43/70）
GT enrichment median = 10.20
target mass median = 0.240
S50 fIoU median = 0.322
S50 fIoU >= 0.3 = 57.14%
S50 fIoU >= 0.5 = 12.86%
```

这表明在相当一部分图片中，确实存在能从自然 Query bbox rows 指向 Reference GT 的单头信号。然而该 oracle 使用 GT 事后挑头，只是上限，不能冒充无 GT head discovery。

### 3. 当前关键缺口

尚未严格计算：

```text
每张图单独运行无 GT LocalizationHeads 算法时，
它选出的 Top1 / Top3 / Top5 / Top10 候选
能否找到该图中由 GT oracle 证明存在的 Reference-responsive head？
```

因此，固定名单失败可能来自两个完全不同的机制：

- 每张图存在有效 head，但 head 编号随样本变化，无法形成固定集合；
- 有效 head 存在，但不满足高 image-attention budget + 低 component entropy 的排序偏好，因而无 GT 算法选不中。

## 可竞争解释

### H1：Reference 信息已在 prompt 阶段写入中间表示

Reference bbox token 与 Reference image 的空间绑定可能主要发生在读取 prompt 时。到自然 Query bbox 生成阶段，模型使用已经写入 residual stream、KV cache 或更高层对象表示的信息，不需要固定 heads 再次把 attention 峰值放回 Reference GT。

可证伪预测：prompt-stage Reference-bbox→Reference 有稳定空间 heads，但 Qbbox→Reference 固定 heads 弱；阻断早期 grounding 或其后续状态传递会影响 Query 定位，即使自然 Qbbox→Reference pointing 不高。

### H2：Reference 回看是 sample-specific dynamic routing

不同图片可能由不同 head 临时承担 Reference 回看，因此 per-image oracle较高，但跨图 frequency 无法收敛为固定名单。

可证伪预测：逐图无 GT Top-k 的“至少一个 head 命中”明显高于固定 Top-k，而各图被选 head ID 的集中度低、跨图 Jaccard 接近随机。

### H3：LocalizationHeads 的无 GT准则与 Reference 信号形态不匹配

有效 Reference head 可能具有较分散的 attention、较低绝对预算，或同时关注目标与 bbox/prompt history；它不一定是最低空间熵 head。算法因此偏好集中在边界、中心或单个背景 token 的稳定偏置头。

可证伪预测：GT oracle head 经常不在无 GT Top10，但 GT-supervised ranking 可在 held-out 样本中找到跨样本可迁移的 heads；有效 heads 的 entropy/image-budget分布与无 GT入选 heads系统不同。

### H4：自然 Query bbox rows 对 Reference 的空间依赖本来就弱

模型生成 Query 坐标时主要依靠 Query 侧定位 heads；Reference 只提供类别、身份或全局匹配信号，不以逐 token Reference 空间 pointing 的形式出现。

可证伪预测：即使使用 discovery GT监督挑选固定 heads，其 held-out Reference pointing/enrichment仍接近随机；per-image oracle与随机极值校正后的优势也不稳定。

### H5：row averaging 掩盖了特定坐标 token阶段

将左括号、数字、逗号和右括号对应的全部 `p−1` rows平均，可能稀释只在某个坐标 token生成前出现的 Reference 回看。

可证伪预测：预注册逐 token/坐标槽位分析显示某些固定阶段具有稳定 Reference pointing；但不得看完结果后事后挑选最佳 token。

## 建议实验 1：逐图无 GT选择能否接近 GT oracle

### 输入与冻结条件

- 仅使用 R-003 的 70 条 selection-held-out records；
- 复用自然 Query bbox `p−1` rows 与 `q_to_r` 全头 artifacts；
- 不重新生成、不 teacher-force GT Query bbox；
- 逐图选择阶段不得读取 Reference GT；
- 严格复用 R-003 的层排除、image-attention threshold、二值 8 邻域 component-token-count entropy 和排序参数。

### 每图输出

```text
no-GT per-image Top1
no-GT per-image Top3 equal mean
no-GT per-image Top5 equal mean
no-GT Top10 candidate set
layer-matched random Top1/3/5
all-head mean
GT oracle Top1（仅作为上限）
```

### 主要指标

- Top1、Top3、Top5 aggregate pointing rate；
- Top10 中至少一头 pointing-hit 的样本比例；
- Top10 中多数 heads 命中的比例；
- Reference GT enrichment、target mass、S50 fIoU；
- 无 GT Top-k 是否包含 GT oracle head；
- 每图入选 head ID 的跨样本集中度、inclusion probability 与 Jaccard；
- 与同层随机和随机极值校正后的 oracle gap。

### 判读

- **逐图无 GT高、固定低：** 支持 sample-specific dynamic heads；
- **Top10 coverage高但Top1/3低：** 候选过滤尚可，entropy排序失败；
- **逐图无 GT低但GT oracle高：** 当前无 GT准则错过有效信号；
- **GT-supervised held-out也低：** 削弱“存在可迁移 Reference localization heads”。

## 建议实验 2：利用 Reference GT 改进算法，但严格区分诊断与无 GT方法

Reference GT 可以用于开发和机制诊断，但必须按 sequence 隔离 discovery/evaluation，防止把 evaluation GT 泄漏进 head选择。

### A. GT-supervised fixed-head discovery

仅在 discovery 70 条中，按每头的以下指标排名：

```text
pointing frequency
median area-normalized enrichment
median target mass
median S50 fIoU
跨图 winsorized / rank-aggregated score
```

冻结 Top3/Top5 后，在 evaluation 70 条上一次性评估。若这套名单有效，而无 GT名单无效，则说明问题主要在选择算法，而非 Reference attention 中完全没有空间信号。

### B. Learn-to-rank / calibration diagnostic

用 discovery GT 学习“哪些无 GT特征能预测空间有效 head”，特征限于部署时不需要 GT的量：

```text
image-attention sum
binary component entropy
component count/size
peak-to-mean ratio
center/boundary mass
跨row一致性
layer/head identity（需强正则或留层验证）
```

在 evaluation 上只用这些无 GT特征选 head，再以 GT评分。该实验可检验是否能从现有算法特征中校准出更好的 Reference-head selector。

### C. Per-image GT label只用于算法误差分解

对每张图定义“有效 head集合”，再测：

- 无 GT候选召回率；
- 候选内排序质量；
- 固定名单覆盖率；
- head ID随样本、对象尺寸、Reference grid coverage和自然行为的变化。

这比只报告 GT oracle 更能解释算法究竟失败在候选过滤、排序还是固定化。

## 与 R-004 的关系

E010-R-004 已批准，回答的是：冻结的 **Query heads** 投向 Reference span 后，是偏向 Reference GT、Query坐标投影、中心/边界还是随机。Q-006 更宽：

- R-004：固定 Query heads 的跨 span 空间偏差；
- Q-006：为什么固定 Reference heads 失败，以及逐图/GT辅助算法能否发现被遗漏的 Reference-responsive heads。

二者互补，不能互相替代。

## 当前判断

> 已有证据不支持“自然 Query bbox生成依赖一批固定且空间有效的 Qbbox→Reference heads”，但支持“部分图片中存在可由GT事后识别的 Reference-responsive单头信号”。当前最关键的未知不是简单的“有没有 Reference head”，而是有效 head 是否样本特异、是否被当前低熵/高预算准则系统漏选，以及 Reference GT监督能否在严格 discovery/evaluation 隔离下发现可迁移的固定 heads或更好的无 GT selector。

status：`investigating / artifact-supported, not validated`。

不得将 per-image GT oracle 解释为可部署的无 GT方法，也不得由 attention pointing 推断身份选择性或因果必要性。

## 后续去向

1. 完成已批准 R-004，先量化 Query heads→Reference 的空间偏差；
2. 新建独立 Run 做 per-image no-GT selection vs GT oracle，不改写 R-003；
3. 若候选召回高但排序失败，再做 discovery-GT calibration；
4. 若 GT-supervised fixed heads 在 held-out 仍失败，转向动态 routing 或早期 Reference grounding→residual/KV传递假设；
5. 只有稳定 observational pattern 后，才考虑因果阻断/patching。
